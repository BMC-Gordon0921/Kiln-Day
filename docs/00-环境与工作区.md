## 2. 终端侧的五个坑（都踩过）

### 2.1 执行策略拦截 `.ps1`

默认 `RemoteSigned`，本地脚本无签名 → `UnauthorizedAccess`。两种解法：

```powershell
# 单次会话内放开（推荐）
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& .\scripts\check.ps1

# 或每个脚本显式带参数
powershell -ExecutionPolicy Bypass -File scripts\check.ps1
```

### 2.2 `pwsh` 不一定在 PATH 上

某些受限会话里 `pwsh` 命令找不到，但 PowerShell 本身可用。脚本之间不要互相 `pwsh -File`，
用 `& (Join-Path $PSScriptRoot 'xxx.ps1')` 进程内调用（`check.ps1` 就是这么写的）。

### 2.3 `.ps1` 必须保持 ASCII

Windows PowerShell 5.1 读取无 BOM 的 UTF-8 文件时按 ANSI 解码，中文注释会被拆成非法字节，
典型报错：`表达式或语句中包含意外的标记 '}'`。所以 `scripts/*.ps1` 全部只写英文注释和英文输出；
需要中文的地方放 `.md` / `.gd`。

### 2.4 中文输出会乱码

Godot/Blender 的输出是 UTF-8，而 PowerShell 管道会按控制台代码页（GBK）重新解码，
中文变乱码。因此 `_env.ps1` 里的 `Invoke-Godot` 用 **cmd 重定向**把原始字节写进日志文件
（`.local\tmp\*.log`，UTF-8），再用编辑器或 `read` 工具查看。脚本自己只 grep ASCII 标记。

### 2.5 ConstrainedLanguage 模式

部分沙箱会话把 PowerShell 降级为 ConstrainedLanguage：`[math]::Round`、`[string]::Format`、
`[IO.Path]::IsPathRooted` 这类 .NET 静态调用会报 `CannotCreateTypeConstrainedLanguage`。
脚本里一律用 PowerShell 原生写法（`-f` 格式化、`-match` 判断路径），不用静态方法。

## 3. 网络现状与「怎么推 GitHub」

实测结论（2026-10-26）：

| 通道 | 状态 | 说明 |
| --- | --- | --- |
| 直连 HTTPS（github.com / api / npm / gitee） | ❌ 不通 | TLS 握手即失败：`SEC_E_NO_CREDENTIALS`，换 openssl 后端则 `Connection was reset` |
| 本地代理 127.0.0.1:7897 | ❌ 无效 | 端口开着但不能承载 HTTPS |
| `Test-NetConnection github.com:22 / :443` | ✅ TCP 可达 | 说明不是网络封锁，是 TLS 凭据/沙箱限制 |
| SSH 认证 `ssh -T git@ssh.github.com` | ✅ 成功 | 返回 `Hi BMC-Gordon0921!`，说明 `~/.ssh/id_ed25519` 可用 |
| `git` 走 SSH（`git clone/remote`） | ⚠️ 沙箱内不可用 | Git for Windows 要 fork MSYS `sh.exe`，报 `couldn't create signal pipe, Win32 error 5` |
| `npm install` | ❌ 不可用 | registry 指向 `mirrors.cloud.tencent.com`，同属 HTTPS |

**结论：** 本工程不依赖联网即可开发与验证。把改动推到 GitHub 有两种方式，都需要在
**你自己的终端**（不受沙箱限制的那个）执行：

```bash
# 方式 A：SSH（已验证可用）
git remote add origin git@github.com:BMC-Gordon0921/Porcelain_Workshop.git
git push -u origin main

# 方式 B：在 GitHub 网页或 GitHub Desktop 里操作
```

首次推送前请先确认 `.gitignore` 生效：`git status` 里**不应**出现 `legacy/`、`.local/`、`game/.godot/`。

> 旧版 three.js 的 Pages 部署工作流（`.github/workflows/deploy-pages.yml`）留在旧仓库里，
> 新工程要发布网页版时另建工作流，且必须先解决导出模板问题（见 §4）。

## 4. ⛔ 缺口：导出模板

`--export-release` / `--export-debug` / `--export-pack` 全都需要导出模板，当前**两处都没有**：

```
C:\Users\<用户>\AppData\Roaming\Godot\export_templates   → 空
.local\appdata\Godot\export_templates                    → 空
```

这意味着：现在只能「编辑器里跑」和「无头跑测试」，**不能产出 exe 或网页版**。

安装模板时注意本工程的特殊约定：`scripts/` 会把 `APPDATA` 重定向到 `.local\appdata`，
所以模板必须放在 **`.local\appdata\Godot\export_templates\4.7.2.stable\`** 才会被脚本看到；
若你直接双击 Godot exe 运行，则要放在真实的 `%APPDATA%\Godot\export_templates\4.7.2.stable\`。
两处都放一份最省心（模板约 1.2 GB）。

模板从哪来（按可行性排）：
1. 在能联网的机器上下载 `Godot_v4.7.2-stable_export_templates.tpz`，拷进上面的目录；
2. Godot 编辑器 → `编辑器 → 管理导出模板 → 从文件安装`；
3. 内网镜像（若有）。

## 5. 音频与字体

- **音乐是 22 MB 的 WAV**（`game/assets/audio/pottery backround music.wav`）。本机没有 ffmpeg，
  Godot 也不能把 WAV 重新编码成 OGG，所以暂时以 WAV 参与构建。发布前需要转成 OGG Vorbis
  （能联网的机器上 `ffmpeg -i in.wav -q:a 4 out.ogg`，体积约降到 1/10）。
- **标题字体是 `.woff2`**（OFL 授权，许可文本随字体放在 `assets/fonts/`）。Godot 只认 TTF/OTF，
  当前用系统字体兜底。拿到 TTF 后替换即可，注意 OFL 要求分发时附带许可文本 —— 别删。

## 6. `.local\` 是什么

```
.local\
  appdata\         APPDATA/LOCALAPPDATA 的重定向目标
  appdata\Godot\   user:// 实际落盘处（存档 save_v1.json 在这里）
  tmp\             Godot 日志、Blender 临时导出
```

可以随时整个删掉（下次运行会重建，存档会丢）。它被 git 忽略，不参与版本管理。

> 为什么要重定向：沙箱会话对 C 盘用户目录的写权限不稳定，Godot 会报
> `Could not open user://` 然后拿不到存档。重定向后 user:// 固定在工作区内。

## 8. 旧版 Web 原型的用法

`legacy/web-demo/` 是旧仓库（commit `03c820c`，即 GitHub `main`）的只读副本，被 git 忽略。
它的价值有两个：

1. **行为 oracle**：`legacy/web-demo/tests/*.test.js` 共 60 项逻辑测试（campaign 9 / experience 6 /
   interaction 11 / journey-update 7 / progression 17 / workshop 10），可离线逐个跑：

   ```powershell
   node legacy\web-demo\tests\workshop.test.js
   ```

   注意要用 `node <文件>` 逐个跑，不要用 `node --test`（沙箱下会因 spawn 管道报 EPERM）。
   S1 移植 `workshop.gd` / `sculpture.gd` 时，用它生成 golden 向量做逐值等价验证。

2. **界面与文案参考**：`src/i18n.js` 里有 810 条中英文词条，S1 抽成 Godot 的 CSV 翻译表。

`legacy/web-demo/node_modules/`（约 59 MB）是为了让那 60 项测试能跑而保留的，可以从备份重建，不要提交。
