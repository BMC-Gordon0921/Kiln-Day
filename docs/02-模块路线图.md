## 3. S1 清单（垂直切片已跑通，2026-10-26）

目标：**一站、一单、从进站到结算完整可玩，能存档续玩。** 不做四站，不做多人。`n`n> 现状：以下 1–5 已在 `game/scenes/workshop/` 落地并用 321 项单测 + 冒烟守住；6 待做。

1. **移植 `sculpture.gd`**（旧 `src/sculpture.js` 426 行，零引擎依赖）
   - `target_pixel` / `create_target` / `make_blank` / `supplied_clay` / `protected_cut`
   - `clay_edge` / `push_clay` / `apply_brush` / `compare_sculpture`
   - 数据结构 `Uint8Array` → `PackedByteArray`，其余逐行照搬
   - 用 `legacy/web-demo/tests/` 生成 golden 向量，逐值核对（见 `docs/04` §3）
2. **移植 `workshop.gd`**（旧 `src/workshop.js` 64 行）
   - `fire_band` / `fire_grade` / `fire_ratio` / `fire_seed` / `create_fire_drift`
   - `order_income` / `format_elapsed` / `clock_policy`
3. **一站场景**：`scenes/site/` —— 进站 → 订单板（3 单）→ 工作台 → 捏塑 → 评分 → 结算
4. **HUD 与结算面板**（Control + Theme，1920×1080 基准，随宽高比伸缩）
5. **存档接线**：结算写盘、启动读盘、`继续游戏`
6. **图鉴最小版**：4 格，显示缩略图 + 名称 + 一句科普
7. **本地化**：`i18n/zh.csv` + `i18n/en.csv`，先覆盖当前用到的约 60 条
8. **音频**：进站音乐（WAV 先用，转 OGG 见 `docs/00` §5）+ 3 个 UI 音效

验收（也是给玩家测的题）：

- 不看说明，3 分钟内做出第一件并过关；
- 关掉游戏再打开，进度、铜钱、图鉴都在；
- 5 人试玩，≥3 人说"想再来一窑"。

## 4. S2 / S3 / S4 的范围切分

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| S2 | 四站铺开 + M2/M4/M6/M7/M8/M9 | 四站 12 单全部可玩；图鉴/成就/剧情不再有"占位符" |
| S3 | M10 多人 | **先做同屏合作**（一台机器两人），跑通再考虑联机；联机要单独评估 |
| S4 | M12 发布 | 导出模板到位，产出 exe + web 两个包，冒烟通过 |

关于多人的直白建议：**别和 1.0 一起发。** 同屏合作成本可控（输入分发 + 状态互斥），
房间联机是另一个量级（同步、掉线、作弊、测试矩阵），以当前 <3 人的规模，
它会把发售时间推后 2–3 个月，而且大概率做不完。放进 1.0 之后当免费更新更稳。

## 5. 三人怎么分工

| 角色 | 主战场 | 不要碰 |
| --- | --- | --- |
| 程序 | M1/M2/M3/M4/M10，工具脚本 | 不要手改 `.blend` 和 `catalog.json` 的文案 |
| 美术 | `art/blender/`、器物/角色建模、UI 图、贴画 | 不要改 `core/` 里的数值 |
| 策划 | `data/catalog.json`（订单/成就/剧情文案）、试玩组织、数值调 | 不要直接改 `.gd` 逻辑 |

策划改 JSON 是**有校验兜底**的：`Catalog.validate()` 会在 Boot 时报错。
所以数据文件可以放心交给非程序改，这是当初选 JSON 而不是 `.tres` 的原因之一。

## 6. 明确不做

- 联机对战、排行榜、云存档；
- 自由建造、换装、季节系统；
- 写实 PBR 材质、复杂粒子——风格是低多边形 + 手绘，用了反而慢；
- 手游/主机移植，S4 之前不评估。

这条清单的用途是：**每次有人说"顺便加一个"时，把它拿出来。**
